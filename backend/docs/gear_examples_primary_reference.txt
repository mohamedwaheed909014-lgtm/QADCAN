LIBRARY PURPOSE
OpenSCAD library for parametric gear racks, involute spur gears, helical gears, herringbone gears, ring gears, bevel gears, spiral bevel gears, worm gears, rack-and-pinion assemblies, and planetary gear assemblies.
The library follows DIN 867 style involute gear assumptions with standard pressure_angle=20 degrees.

GEARS-MASTER DESIGN RULES TO PRESERVE
- Use "modul" as the module parameter when following the library exactly.
- Use "tooth_number" for single gears and "gear_teeth", "pinion_teeth", "sun_teeth", "planet_teeth" for assemblies.
- Use "width" for cylindrical gear face width and "tooth_width" for bevel gear tooth face width.
- Use "bore", "gear_bore", "pinion_bore", "worm_bore", or "gear_bore" as separate shaft openings.
- Use "pressure_angle=20" by default.
- Use "helix_angle=0" for straight teeth, nonzero helix_angle for helical or spiral-looking teeth.
- Helical and herringbone gears adjust the transverse pressure angle to helix_angle.
- Herringbone gears mirror two helical halves and reduce or cancel axial thrust.
- "optimized=true" creates material reduction / surface improvement features when geometry allows.
- "together_built=true" renders assemblies meshed together; false is useful for print layout.
- For 3D printed gear assemblies, include adequate clearance and avoid fused planet/ring meshes.
- For generic prompts with missing dimensions, use the defaults shown in the example calls below.
- Do not output a placeholder module asking for modul, tooth_number, bore, etc.; generate a complete usable example instead.
- Do not use echo("Please specify ...") for gear requests unless the user explicitly asks for an interactive parameter template.

TYPE MAPPING FOR USER PROMPTS
- "spur gear" -> spur_gear
- Plain spur gear must use helix_angle=0.
- "spiral gear" or "helical gear" -> spur_gear with nonzero helix_angle
- "herringbone gear" or "double helical gear" -> herringbone_gear
- "ring gear" or "annulus" -> ring_gear or herringbone_ring_gear
- "rack" -> rack or mountable_rack
- "rack and pinion" -> rack_and_pinion
- "bevel gear" -> bevel_gear
- "bevel pair", "miter gear", "right angle gear pair" -> bevel_gear_pair
- "spiral bevel gear" -> spiral_bevel_gear for single gear, or bevel_gear_pair with nonzero helix_angle for pair-style output
- "bevel herringbone" -> bevel_herringbone_gear or bevel_herringbone_gear_pair
- "planetary gear", "epicyclic gear", "sun and planet gear", "planet gear assembly" ->
    planetary_gear(modul, sun_teeth, planet_teeth, number_planets, width, rim_width, bore, together_built=true)
    ONE call renders sun + planets + ring. NEVER use a for-loop of spur_gear() calls.
- "worm" -> worm
- "worm gear", "worm drive", "worm and wheel" -> worm_gear

FORMULA AND PLACEMENT GUIDANCE
- Spur/helical center distance for two external gears: modul / 2 * (teeth_a + teeth_b).
- Rack and pinion axis distance from rack pitch line: modul / 2 * gear_teeth.
- Planetary center distance from sun to planet: modul / 2 * (sun_teeth + planet_teeth).
- Planetary outer diameter with rim: modul * (sun_teeth + 2 * planet_teeth + 2.333) + 2 * rim_width.
- Planetary ring tooth count is implied by sun and planet teeth: ring_teeth = sun_teeth + 2 * planet_teeth.
- For bevel pairs, use axis_angle and matching cone geometry; do not render two flat spur gears.
- For worm drives, use thread_starts, lead_angle, length, worm_bore, and gear_bore as explicit parameters.

BEVEL / SPIRAL BEVEL GEAR PAIR — CRITICAL RULES
- gear_teeth is the LARGER wheel (more teeth); pinion_teeth is the SMALLER pinion (fewer teeth).
  Example: user says "16:32" → pinion_teeth=16, gear_teeth=32.
- A spiral bevel gear pair uses bevel_gear_pair with a nonzero helix_angle (e.g. 30°).
  The library automatically negates helix_angle for the pinion to achieve proper hand matching.
- gear_bore and pinion_bore are subtracted INSIDE the library. Pass the real bore values directly.
  NEVER pass gear_bore=0 or pinion_bore=0 and then subtract cylinders manually in a difference() block.
- OpenSCAD modules do NOT return values. NEVER write: body = bevel_gear_pair(...); — that is invalid.
  Call the module directly: bevel_gear_pair(modul=..., gear_teeth=..., ...);

OUTPUT GUIDANCE
- If the generated OpenSCAD can depend on the external library, write a short file that includes gears.scad and calls the correct module.
- For a plain spur gear, do not use helix_angle=20 or any nonzero helix_angle; that creates a helical/slanted gear shape.
- Do not hand-build spur teeth from rectangular cubes when gears.scad is available; use spur_gear(...) for a clean involute-style gear.
- If the output must be standalone, implement simplified but faithful equivalents while preserving gears-master parameter names, proportions, and formulas.
- Never ignore the requested gear type. A bevel gear must be conical. A worm gear must include a worm screw and wheel. A planetary gear must include sun, planets, ring, and carrier or at least their correct spatial relationship.
- For planetary gears: call planetary_gear() ONCE. Do NOT write a for-loop that translates
  individual spur_gear() or herringbone_gear() calls around a circle — that renders only
  planet shapes without a sun gear or ring gear and is always wrong.
- planetary_gear() internally calls herringbone_gear() for all parts. The rendered output
  will always have herringbone (double-helical) teeth regardless of helix_angle value.
